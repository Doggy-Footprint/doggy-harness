### harness에서 찾은 것

- brief 마커 뒤에 출력 리다이렉션(`>/dev/null 2>&1`)을 붙이면 telemetry에 기록되지 않습니다. 2차에서 `base`는 7회 중 5회가 이렇게 실행해 2회만 기록됐고, `late`는 7회 모두 리다이렉션 없이 실행해 7회 기록됐습니다.
- 로컬 세션 기록의 Bash 명령을 0.52.0 파서와 고친 파서로 다시 읽었습니다. 마커를 실제로 실행한 명령만 세면(heredoc 본문, grep 패턴, PR 본문에 마커 문자열이 들어 있을 뿐인 명령은 뺍니다) 실제 작업 세션은 18건 중 0.52.0 파서가 10건, 고친 파서가 17건을 기록합니다. 다른 세션의 평가 실행은 208건 중 71건과 204건입니다. 남는 5건은 run id를 셸 변수로 넘긴 경우입니다. (실행 건수는 파서와 따로 만든 정규식으로 셌습니다. 고친 파서는 줄바꿈을 명령의 끝으로 보고, heredoc 본문과 리다이렉션을 건너뜁니다.) 고친 파서가 놓치고 0.52.0 파서가 기록하는 명령은 없습니다. (처음 적은 "33건 중 9건"은 마커를 언급만 한 명령 15건을 분모에 넣은 잘못된 수치였습니다.)
- run id를 모델이 만듭니다. 난수 명령이 막히면 `7c3e91a4b2d85f06`, `3f9a1c7e5b2d4086`처럼 서로 거의 같은 값을 손으로 적습니다. `late`의 1차 형태(명령에 id를 넘김)에서는 4회 모두 id를 셸 변수로 넘기려 했습니다.
- `base`는 `facts.md`를 7회 중 6회 `head -50`으로 잘라 읽었습니다(본문은 전부 읽으라고 합니다).
- 첫 메시지 전에 try-n-fail을 읽은 실행이 `base` 2회, `late` 1회 있었습니다.

### 실행기에서 찾아 고친 것

- 권한 거부 이벤트의 `message`가 문자열이어서 기록 해석이 죽고, 한 실행의 예외가 전체를 멈췄습니다. 해석을 고치고 실행마다 예외를 가뒀습니다.
- run id를 만드는 `python3 -c "import secrets…"`가 거부되어 `late` 쪽이 더 많이 재시도했습니다. 그 명령을 허용했고, `late` 변형은 phase 명령이 run id를 발급하도록 바꿨습니다(이제 phase 명령이 7회 모두 첫 호출입니다).
- 모델이 메시지를 쓴 뒤 마커를 실행하고 한 줄을 덧붙이면 그 한 줄만 첫 메시지로 저장됐습니다(14회 중 1회). 가장 긴 본문부터 끝까지를 저장하도록 고쳤습니다.

### 남은 것

- 사례가 쓰는 저장소 둘(openreply, crm)은 설치 과정에서 원래 `AGENTS.md`가 `agent-docs/logs/`로 옮겨집니다. 그래서 crm 사례를 A17, A19에서 빼는 규칙은 이 실행기에서는 필요 없을 수 있습니다. 두 변형에 똑같이 적용되므로 비교에는 영향이 없습니다.
- 실행 환경의 플러그인 하나(`orca-agent-view`)가 `--setting-sources project`와 무관하게 실행에 들어옵니다. 기준선 측정에도 같았습니다.
