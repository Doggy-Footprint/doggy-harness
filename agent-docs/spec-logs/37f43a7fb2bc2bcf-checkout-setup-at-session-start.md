# Scope
In scope: a Claude Code `SessionStart` hook and a command-line tool that, in a checkout where the harness is installed, (a) install the lockfile's dependencies in a detached background process when a verification tool declared in the project manifest is not present in the checkout, for Python (uv, Poetry, PDM) and JavaScript (pnpm, Yarn, Bun, npm); (b) set `core.hooksPath` to `.harness/git` when the clone has none and no hook manager; the report of a running or failed install in the `phase` command's output and the start of a first install from it; the installer changes that ship them (hook entry, `.gitignore` line, config default, version 0.54.0 with its migration announcement); README text.
Out of scope: sharing an environment between checkouts by symlink; changing or creating a lockfile; adding a tool to a manifest (still offered by `harness.py install|update`); Rust (`cargo-mutants` is installed machine-wide and recorded in no repository file) and Go (the tool is built on demand); a Codex hook entry; Windows; checking the installed version of a tool; waiting for an install inside the workflow; sharing the main checkout's `node_modules` with local worktrees (todo `8f0d4c2a6b1e9a37-share-node-modules-across-worktrees.md`); running `npm ci` over an existing `node_modules`; the zero-kill test check (todo `31b266665f55f0b4-zero-kill-test-check.md`); any change to skill, phase-rule, or agent text.

# Signatures
```
python3 .harness/bin/checkout_setup.py hook                      # SessionStart entry; hook JSON on stdin; notice lines on stdout; exit 0
python3 .harness/bin/checkout_setup.py status [--wait SECONDS]   # status lines on stdout; exit 0
python3 .harness/bin/checkout_setup.py run --checkout PATH [--retry-failed]   # worker; not for direct use; exit 0
python3 .harness/bin/workflow_marker.py phase ...                # existing; gains the lines of F11
```
Files written, all under `<checkout>/.harness/sessions/checkout-setup/`:
- `state.json` — `{"languages": {"<language>": {"result": "ok", "verified": <bool>, "lock_sha": "<sha256 hex of the lockfile bytes>", "command": "<command string>", "finished": <epoch seconds>} | {"result": "failed", "reason": "<text>", "lock_sha": ..., "command": ..., "finished": ...}}}`. An entry or file that does not have this shape counts as absent.
- `lock` — `{"pid": <int>, "started": <epoch seconds>, "commands": ["<command string>", ...]}`.
- `install.log` — appended: each command line followed by that command's stdout and stderr.

Environment: `git` and the package managers are looked up on `PATH`; `HARNESS_PREFERENCES_FILE` (existing; default `~/.harness/preferences.json`); `HARNESS_CHECKOUT_SETUP_TIMEOUT` (positive integer seconds per command; default 1800; any other value means the default).

Languages, tools, and commands (language order: python, javascript; package order as listed):

| language | manifest | tools | lockfile → command, first match wins |
| --- | --- | --- | --- |
| python | `pyproject.toml` | `hypothesis`, `mutmut` | `uv.lock` → `uv sync --frozen --inexact`; `poetry.lock` → `poetry install --no-interaction`; `pdm.lock` → `pdm install --frozen-lockfile` |
| javascript | `package.json` | `fast-check`, `@stryker-mutator/core` | `pnpm-lock.yaml` → `pnpm install --frozen-lockfile`; `yarn.lock` → `yarn install --frozen-lockfile`; `bun.lock` or `bun.lockb` → `bun install --frozen-lockfile`; `package-lock.json` → `npm ci` |

`npm ci` is the one command of the table that *replaces the environment*: it deletes `node_modules` before installing.

Notice lines (`<commands>` is the command strings joined by ` && `; `<n>` is `now − lock.started` in whole seconds):
- M-HOOKS: `harness: set git core.hooksPath=.harness/git in this clone`
- M-START: `harness: installing project dependencies in the background: <commands>. Verification tools are not runnable in this checkout until it finishes; check with: python3 .harness/bin/checkout_setup.py status`
- M-RETRY: `harness: the last dependency install failed (<reason>); retrying in the background: <commands>. Verification tools are not runnable in this checkout until it finishes; check with: python3 .harness/bin/checkout_setup.py status`
- M-RUNNING: `harness: a dependency install is running in this checkout (<commands>, started <n>s ago). Verification tools are not runnable in this checkout until it finishes; check with: python3 .harness/bin/checkout_setup.py status`
- M-FAILED: `harness: the last dependency install failed (<language>: <reason>); verification tools are not runnable. Run manually: <command>; log: .harness/sessions/checkout-setup/install.log`
- M-NOMANAGER: `harness: verification tools are declared but not installed (<executable> not found on PATH); run manually: <command>`
- M-MANUAL: `harness: verification tools are declared but not present in node_modules; "<command>" would delete and reinstall node_modules, so it is not run automatically. Run manually: <command>`

Status lines:
- S-RUNNABLE: `<language>: runnable (<declared tools joined by ", ">)`
- S-OFF: `<language>: not installed (automatic install is off)`
- S-NOLOCK: `<language>: not installed (no lockfile)`
- S-SETTLED: `<language>: installed by "<command>"; not found in the checkout`
- S-NOMANAGER: `<language>: not installed (<executable> not found on PATH); run manually: <command>`
- S-FAILED: `<language>: install failed (<reason>); run manually: <command>; log: .harness/sessions/checkout-setup/install.log`
- S-MANUAL: `<language>: not installed ("<command>" would delete and reinstall node_modules); run manually: <command>`
- S-PENDING: `<language>: not installed (install not started)`
- S-RUNNING: `<language>: install running (started <n>s ago)`
- S-NONE: `no verification tools declared in this checkout`

Migration announcement lines of 0.54.0, label `install declared verification tools and restore git hooks at session start`:
- `a Claude SessionStart hook installs the lockfile's dependencies in the background when a verification tool declared in the project manifest is not present in the checkout, and sets core.hooksPath to .harness/git in a clone that has no hook manager`
- `set "auto_install": false in .harness/config.json to turn the automatic install off`
- `no data is migrated`

# Functional Requirements
| id | requirement | priority | source |
| --- | --- | --- | --- |
| F1 | **Checkout.** `hook` takes the directory from the payload's `cwd` when that is a non-empty string, otherwise the process working directory, and resolves the checkout with `git -C <directory> rev-parse --show-toplevel`. `status`, the worker without other input, and the phase command use the checkout that contains the running script. A checkout is *installed* when `<checkout>/.harness/manifest.json` is a file. Outside an installed checkout every command of this spec prints nothing, starts nothing, and changes nothing. | must | I1 |
| F2 | **Declared and present.** A python tool is *declared* when its normalized name (lowercase; each run of `-`, `_`, `.` replaced by `-`) equals the leading requirement name of any string value or any key at any depth of the parsed `pyproject.toml`. A javascript tool is declared when it is a key of `dependencies`, `devDependencies`, `optionalDependencies`, or `peerDependencies` of `package.json`. A manifest that is absent, unreadable, unparseable, or (for JSON) not an object, or a missing TOML parser, declares nothing. A python tool is *present* when a path `<checkout>/.venv/lib/python*/site-packages/<name>` or `<checkout>/.venv/Lib/site-packages/<name>` exists; a javascript tool when `<checkout>/node_modules/<name>/package.json` is a file. | must | I1 |
| F3 | **Command.** The lockfile and command of a language are chosen by the table in Signatures, first match in the listed order. Commands run as the fixed argument lists of that table: no part of a command comes from a repository file. The executable is looked up on `PATH` when a decision is made and again when the worker runs it. | must | I1, I4 |
| F4 | **Language state.** For each language whose manifest exists, the first matching state holds: `undeclared` (no tool declared); `runnable` (every declared tool present); `off` (F5); `no-lockfile` (no lockfile of the table exists); `settled` (the state entry has `result` `ok`, `verified` false, and `lock_sha` equal to the current lockfile's hash); `no-manager` (the executable is not on `PATH`); `failed` (the state entry has `result` `failed` and `lock_sha` equal to the current hash); `manual` (the chosen command replaces the environment and `<checkout>/node_modules` exists); `pending` (otherwise). | must | I1, I3 |
| F5 | **Off.** Automatic install is off when `<checkout>/.harness/config.json` exists and is not a JSON object, or is an object whose `auto_install` is `false`; or when the preferences file holds `repositories[<path>].verification_tools_prompt == "never"` for the resolved path of the checkout or of the directory that contains the git common directory (the main worktree). An absent config file, any other `auto_install` value, and an absent or unreadable preferences file leave it on. | must | I4, user decision |
| F6 | **Ensure.** Given a flag `retry_failed`: when a live lock exists (F8), print M-RUNNING and start nothing. Otherwise the *install set* is every `pending` language plus, when `retry_failed`, every `failed` language. When the set is not empty, start one detached worker (own session, stdin closed, output to `install.log`), run by the interpreter that is running the command and with its environment, not by a `python3` looked up on `PATH`, and print M-RETRY if a language of the set was `failed` (its reason; the first in language order when several), else M-START. Then, in language order, print for each language outside the install set the line of its state: M-NOMANAGER for `no-manager`, M-FAILED for `failed`, M-MANUAL for `manual`. Other states print nothing. No command of this spec waits for the worker except `status --wait`. The call returns without waiting for the worker. | must | I1, I3, user decision |
| F7 | **Worker.** The worker creates the state directory and takes the lock by exclusive creation; when a live lock exists it exits without running anything; a stale lock is replaced. It computes the install set again by F4–F6 with its own `--retry-failed` flag and runs each language's command in language order with the checkout as working directory, stdin closed, and the per-command timeout. After each command it writes that language's state entry, keeping other entries, by writing a temporary file and renaming it: exit status 0 gives `result` `ok` with `verified` equal to whether every declared tool is now present; otherwise `result` `failed` with `reason` `exit <code>` followed, when there is output, by `: ` and the first non-empty line of stderr, or of stdout when stderr has none, stripped and cut to 200 characters; a timeout gives `timeout after <seconds>s`; a launch failure gives `<exception class name>: <first line of its message>`. It removes the lock at the end and exits 0. | must | I1, I3 |
| F8 | **Lock.** A lock is live when the file has the shape of Signatures, the process `pid` exists, and `now − started` is at most twice the per-command timeout. Any other lock is stale and counts as absent. | must | I1 |
| F9 | **Hooks path.** In an installed checkout `hook` reads `git config --get core.hooksPath`. It sets `core.hooksPath` to `.harness/git` and prints M-HOOKS only when the value is empty, none of `.husky/pre-commit`, `lefthook.yml`, `lefthook.yaml`, `.lefthook.yml`, `.pre-commit-config.yaml` exists in the checkout, and `<checkout>/.harness/git/pre-commit` is a file. This does not depend on F5. | must | I2, user decision |
| F10 | **Hook.** `hook` performs F9, then F6 with `retry_failed` true, and prints the resulting lines on stdout, M-HOOKS first. It exits 0 in every case, and on any failure of its own (malformed input, unreadable files, git unavailable) prints no traceback. | must | I1, I2 |
| F11 | **Phase command.** `workflow_marker.py phase` without `--again` performs F6 with `retry_failed` false; with `--again` it prints the lines F6 would print without starting a worker (M-RUNNING, M-NOMANAGER, M-FAILED, M-MANUAL; nothing for `pending`). The lines are placed after the existing header lines and before the blank line that precedes the rules. When there is no line the output is byte-identical to the output before this change. A failure in this step never changes the rest of the output. | must | I3 |
| F12 | **Status.** `status --wait N` (non-negative integer) first waits until no live lock exists or N seconds have passed. `status` then prints, for each language that declares a tool, in language order, the line of its state: S-RUNNABLE, S-OFF, S-NOLOCK, S-SETTLED, S-NOMANAGER, S-MANUAL; for `failed` and `pending`, S-RUNNING when a live lock exists, else S-FAILED and S-PENDING. # Errors
- Install command exits non-zero — state entry `failed` with the `exit <code>` reason; M-FAILED from the phase command, M-RETRY at the next `hook` — lock removed, other languages' entries kept, no tracked file changed by harness code.
- Install command exceeds the timeout — state entry `failed`, reason `timeout after <seconds>s` — the command's process is killed, lock removed.
- Manager executable not on `PATH` — M-NOMANAGER / S-NOMANAGER — no worker, no state change.
- A declared tool is missing from an existing `node_modules` of an npm project — M-MANUAL / S-MANUAL — no worker, `node_modules` untouched.
- Worker killed before finishing — no signal at that moment — the lock becomes stale once its process is gone; the language has no new entry and is `pending` again.
- Malformed hook payload, state file, lock file, config, or manifest — exit 0, no traceback — malformed state or lock counts as absent; malformed config turns the install off; a malformed manifest declares nothing.
- Checkout not installed, or not a git work tree — no output — nothing started, no git config change.
- `git config` cannot write `core.hooksPath` — no M-HOOKS — value unchanged; the install part still runs.
- A failure inside the phase command's F11 step — none — the phase rules print in full.
