Carry audit state between fresh verifiers. Acceptance is scoped to the spec version, evidence revision, and dependencies, not a permanent exemption. After changes to requirements, tests, helpers, procedures, or implementation behavior, mark affected entries invalidated and record the impact and why the other entries remain valid; a changed shared helper can invalidate several obligations. A verifier checks this impact assessment against the Tests diff file and reopens acceptance only with new evidence of a defect, changed dependency, or missed requirement. Never inherit acceptance blindly or restart scope derivation merely because the verifier is fresh.
