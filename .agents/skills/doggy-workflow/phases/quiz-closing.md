At each closing, judge each question: *invalid* when an amendment removed or changed what it asks about, or when its expected answer misread the approved spec; *not yet built* when its `built by` step is not `done` (in a spec without steps, until the run meets the stop condition); *valid* otherwise. Only an amendment writes `invalid v<n> — <reason>` into the spec; never write *not yet built*.

1. *Completion check*: for a run that meets the stop condition, before setting `complete`, over every valid question, asked or not. Answer each from the built result before rereading its expected answer: reason from the built structure and its behavior on the main path, and cite the code location or run each answer rests on. Then compare. Where the result differs from the approved spec, correct it (Workflow item 7). Where the expected answer misread the approved spec, mark the question invalid by a contract-only amendment and report it; never rewrite an expected answer after approval. A question that only one test case could settle breaks the rules above: mark it invalid the same way.
2. *Closing quiz*: in every closing report, ask the user up to 3 valid questions whose `asked` is `no`, covering the trade-off, an engineer call, and the final shape as far as they allow, and write `closing <date>` into their `asked` cells. A `limit`, nonterminal, or aborted closing skips the completion check and asks only questions already built. When no question qualifies, write one new question and its expected answer in the picks file before sending. Report invalid questions and why in *Numbers*, with the completion check's differences and how each was resolved.
