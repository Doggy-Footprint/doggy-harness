5. **Verify (fresh test-verifier).** The verifier has no shell, so after a passing Test command main writes the Tests diff file: `git diff <base_commit> -- <Tests paths>` followed by the list from `git ls-files --others --exclude-standard -- <Tests paths>` as new files, saved outside the working tree (the session scratchpad when there is one) so it is neither committed nor counted as a project change. Rewrite it for every dispatch.
   - Before dispatch, check and persist the incremented `verifier invocations` count in Workflow Control. A run allows at most two invocations, or two per step in a stepped spec, counting the initial audit and failed, interrupted, or incomplete audits. Resume and spec amendments preserve the count; replacement runs must not evade the limit. Apply the stop condition if the required audit would exceed the budget. Use the run's total invocation count for telemetry `--round`.
   - Dispatch a fresh verifier with the spec path/version, complete coverage/evidence map, audit state, change-impact assessment, finding ledger, and the Tests diff file's path. Check every obligation has a current disposition; audit pending and invalidated evidence and assess any new challenge to retained acceptance.
